## 4. 分层与依赖

### 4.1 分层架构

```
interfaces → application → domain ← infrastructure
```

### 4.2 依赖规则

- `interfaces` 只做入参校验、DTO 转换、调用应用服务
- `application` 负责业务编排，不直接持久化
- `domain` 承载业务规则，不依赖外层
- `infrastructure` 实现仓储、缓存、外部适配

## 5. 多模块与服务拓扑

### 5.1 Maven 多模块基线

```text
backend/<project-name>-parent
├── parent(pom)               # 仅版本与依赖管理
├── <project-name>-common     # 公共模块
├── <project-name>-admin-service
└── <project-name>-app-service（多端场景）
```

### 5.2 模块职责

| 模块 | 职责 | 是否强制 |
|---|---|---|
| parent | 版本与插件管理，不承载业务代码 | 是 |
| common | 统一返回体、错误键、通用异常 | 是 |
| admin-service | 后台管理业务能力 | 是 |
| app-service | 移动端/小程序端业务能力 | 多端场景强制 |

### 5.3 接口边界

| 接口域 | 路径前缀 | 调用方 |
|---|---|---|
| 外部接口 | `/api/v1/**` | 前端/外部客户端 |
| 内部接口 | `/internal/v1/**` | 微服务间调用 |
