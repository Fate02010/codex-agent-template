# docs/AGENTS.md — 文档规范

## 1. 总则

本项目采用文档驱动开发，文档既是输入也是输出。所有文档以冻结后的版本为准，不脑补业务。

## 2. 目录结构

```
docs/
├── AGENTS.md                      # 本文件：文档规范
├── 01-requirements/               # 需求文档
│   ├── PRD_REVIEW_ISSUES.md       # PRD 评审问题清单
│   └── PRD_RECTIFIED.md           # 整改后 PRD
├── 02-architecture/               # 设计文档
│   ├── ARCHITECTURE.md            # 架构设计
│   ├── API_CONTRACT.md            # 接口契约
│   └── DATA_MODEL.md              # 数据模型
└── 03-testing/                    # 测试文档
    ├── TEST_PLAN.md               # 测试计划
    └── TEST_CASES.md              # 测试用例
```

## 3. 文档命名规范

- 使用全大写 + 下划线命名：`PRD_RECTIFIED.md`、`API_CONTRACT.md`
- 目录使用序号前缀：`01-requirements`、`02-architecture`、`03-testing`
- 禁止中文文件名

## 4. 文档标记规范

在文档内容中使用以下标记标注变更：

| 标记 | 含义 | 使用场景 |
|---|---|---|
| 【新增】 | 新增内容 | 首次添加的需求、接口、字段 |
| 【修改】 | 修改内容 | 对已有内容的调整 |
| 【删除】 | 删除内容 | 移除的需求、接口、字段 |
| 【待确认】 | 待确认 | 需要产品/业务方确认的内容 |
| 【风险】 | 风险项 | 技术风险、业务风险、依赖风险 |

## 5. 文档结构要求

每份文档至少包含以下章节：

| 章节 | 说明 |
|---|---|
| 目标 | 本文档要解决什么问题 |
| 范围 | 涉及哪些模块、功能 |
| 正文 | 具体内容（流程、字段、规则等） |
| 异常与边界 | 异常场景、边界条件 |
| 变更记录 | 版本号、日期、变更说明 |

## 6. 文档引用关系

```
PRD_RECTIFIED.md（需求）
    ↓
ARCHITECTURE.md（架构） → API_CONTRACT.md（接口） → DATA_MODEL.md（数据）
    ↓
TEST_PLAN.md（测试计划） → TEST_CASES.md（测试用例）
```

- 设计文档必须引用需求文档中的功能编号
- 测试用例必须引用需求文档中的功能编号和接口文档中的接口编号
- 需求引用格式：`关联需求：F001`（在 Skill 输出和用例中使用）
- 接口引用格式：`关联接口：API-XXX-001`
- 跨文档引用格式：`参见 PRD_RECTIFIED.md § F001`

## 7. 文档优先级

以冻结后的文档为准。当文档与代码冲突时：

1. 先确认文档是否为最新版本
2. 如果文档是最新的，以文档为准修改代码
3. 如果需要变更需求，先更新文档，再改代码

## 8. 禁止事项

- 禁止在文档中写代码实现细节（伪代码和流程图除外）
- 禁止跳过文档直接写代码
- 禁止文档和代码不同步
