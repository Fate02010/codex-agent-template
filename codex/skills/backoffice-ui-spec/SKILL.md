# Skill: backoffice-ui-spec — 后台高保真设计规范

## Purpose

输出后台管理页面的统一设计规范，约束信息层级、主次操作、字段展示、文案、状态标签与反馈规则，避免原型生成出现不符合业务用户习惯的排版和交互。

本 Skill 产出的规范用于被下游 Skill 直接消费，不替代业务需求、架构设计和代码实现。

## When to Use

- 需要生成后台管理高保真原型（display / acceptance）且希望先冻结布局与交互规范。
- 当前项目出现信息层级混乱、主按钮不唯一、技术字段直出、文案研发化、状态反馈不一致等问题。
- 需要为 `ui-design-spec`、`prototype-build`、`prototype-check` 提供统一门禁依据。

## When Not to Use

- 仅做移动端或营销落地页视觉探索。
- 仅做业务需求梳理但尚未进入 UI 基线阶段。
- 直接生成 HTML 原型（应使用 `prototype-build`）。

## 执行层级导读（Progressive Disclosure）

- `P0 必检（阻塞）`：`BO-RULE-001~023` 中的 Fail-fast 项必须完整定义并可判定；任一缺失必须 FAIL。
- `P1 扩展（覆盖）`：自动化映射、下游消费映射、模板片段复用完整。
- `P2 参考（说明）`：示例、版本记录、背景说明仅作参考，不得覆盖 `P0` 结论。
- 执行顺序必须为：先过 `P0 Gate`，再进入 `P1`；`P2` 不参与放行判定。

## Rules

1. 规范默认适用桌面后台（`>=1200`），移动端仅定义降级可读规则，不扩展为完整移动后台规范。
2. 文案口径默认纯中文业务文案；技术字段仅允许出现在字段映射表，不得在展示文案中直出。
3. 规范必须覆盖以下 23 条强制规则（`BO-RULE-001~023`），任一缺失视为规范不完整：
   - `BO-RULE-001`：信息层级清晰（页面目标、主任务、首屏决策信息）
   - `BO-RULE-002`：主操作唯一（每页仅 1 个主按钮，位置固定）
   - `BO-RULE-003`：操作优先级（主/次/危险分级，危险动作不得与主操作同层抢焦点）
   - `BO-RULE-004`：字段展示映射（技术字段 -> 业务中文标签）
   - `BO-RULE-005`：文案中文化（禁 `from_status/to_status/biz_id/user_id` 等技术字段直出）
   - `BO-RULE-006`：状态标签语义（颜色语义、禁用态、可点击态）
   - `BO-RULE-007`：反馈闭环（空态、加载态、失败态、成功态）
   - `BO-RULE-008`：表格/筛选/分页闭环（筛选动作、结果反馈、分页区完整）
   - `BO-RULE-009`：主操作语义一致（主按钮文案含“选中/批量”时必须存在选择机制与已选反馈）
   - `BO-RULE-010`：页面区块白名单（页面出现的功能卡片/区块必须在白名单声明；白名单不得豁免禁入区块）
   - `BO-RULE-011`：页面类型与布局模板匹配（查看型/维护型/处理型）；当布局模板为“列表主视图”时必须满足“筛选区 -> 结果区 -> 分页区”三段式
   - `BO-RULE-012`：主任务首屏可见（首屏必须看到主任务关键区块）
   - `BO-RULE-013`：列表前置重表单限制（禁止上重表单下长列表压制主任务；禁止在列表主视图结果区下方放置业务处理区）
   - `BO-RULE-014`：跨屏依赖禁止（关键任务路径滚动预算默认 <= 1 屏）
   - `BO-RULE-015`：双主流程冲突禁止（同页双主流程/双主按钮抢焦点）
   - `BO-RULE-016`：工具栏顺序规范（筛选 -> 结果 -> 分页）
   - `BO-RULE-017`：列表闭环优先级（筛选/表格/分页/结果计数主视图优先；不允许下置业务工作台/处理卡片与列表主流程并列抢焦点）
   - `BO-RULE-018`：行操作一致性（行操作列位置与入口一致）
   - `BO-RULE-019`：批量操作语义一致（批量文案必须绑定选择机制）
   - `BO-RULE-020`：表单复杂度分层（复杂表单需分组/页签/分步）
   - `BO-RULE-021`：分页语义与可达性（prev/next/page/total/current 完整可达）
   - `BO-RULE-022`：筛选后分页重置（筛选/排序后默认回到第一页）
   - `BO-RULE-023`：认知负荷控制（筛选字段 <= 8、操作按钮 <= 5、表单字段 <= 15、表格列 <= 10）
4. 每条 `BO-RULE` 必须提供“检查方式 + 失败判定 + 修复建议”，确保可执行、可判定。
5. 规范必须声明与既有 `BUILD-RULE-001~015`、`UX-TARGET-*` 的关联映射，不得形成两套冲突标准。
6. 若信息不足，使用 `【待确认】` 标记；不得自行发明未定义业务动作。
7. 冷启动规则（强制）：
   - 若 `docs/02-design/` 不存在，先创建目录。
   - 若 `BACKOFFICE_UI_SPEC.md` 不存在，按本 Skill 内置结构创建完整文档。
   - 若文档状态为 `模板`，整文件覆盖为正式产物结构。
   - 若文档状态不为 `模板`，按章节标题增量更新，不按章节序号硬编码。
8. 自动化检查映射（强制）：
   - 每条 `BO-RULE` 必须补充“自动化检查映射”字段：
     - 检查对象（DOM/截图/点击）
     - 选择器（或截图区域）
     - 预期行为
     - 判定阈值
     - 证据落点（截图路径/DOM 片段/步骤）
	 - 映射目标必须可被 Playwright + Chromium 自动消费
9. 规则去重约束（强制）：
   - `Rules` 负责规则主定义。
   - `Workflow` 与 `Quality Gate` 仅引用规则编号与判定结论，不重复整段规则文本。

### 步骤 1：提取后台页面与关键任务

- 从 `PRD_RECTIFIED.md` 提取后台页面、关键任务、角色、字段与状态。
- 从 `MVP_SCOPE.md`、`OUT_OF_SCOPE.md`、`<current-change>` 提取范围边界。
- 若存在 `SCREEN_INVENTORY.md`，读取页面编号与页面类型，建立规范映射基线。

### 步骤 2：编写 23 条强制规则（BO-RULE-001~023）

每条规则按统一结构输出：

- 规则编号
- 规则描述（必须/不得）
- 检查方式（如何验证）
- 失败判定（触发阻塞条件）
- 修复建议（可执行动作）

### 步骤 2.6：编写 BO-RULE-023（认知负荷控制）

**BO-RULE-023：认知负荷控制**

- 规则描述：
  - 列表页筛选字段不得超过 8 个（常用筛选字段 <= 5 个，高级筛选字段 <= 3 个）
  - 页面操作按钮不得超过 5 个（主操作 1 个，次操作 <= 3 个，危险操作 <= 1 个）
  - 表单字段不得超过 15 个（基础信息 <= 10 个，扩展信息 <= 5 个）
  - 表格列不得超过 10 列（核心列 <= 6 列，扩展列 <= 4 列）
- 检查方式：
  - 统计筛选字段数量
  - 统计操作按钮数量
  - 统计表单字段数量
  - 统计表格列数量
- 失败判定：
  - 筛选字段 > 8 个，判定为 `重要（Major）`
  - 操作按钮 > 5 个，判定为 `重要（Major）`
  - 表单字段 > 15 个，判定为 `重要（Major）`
  - 表格列 > 10 列，判定为 `重要（Major）`
- 修复建议：
  - 筛选字段过多：将低频筛选字段收起到“高级筛选”或“更多筛选”
  - 操作按钮过多：将低频操作收起到“更多操作”下拉菜单
  - 表单字段过多：使用分组、页签或分步表单
  - 表格列过多：将低频列隐藏到“列设置”或“更多列”

### 步骤 2.5：强化列表主视图结构阻塞规则（BO-RULE-011/013/017）

- 在 `BO-RULE-011` 中必须写明：`data-layout-template=列表主视图` 时，页面主结构必须为“筛选区 -> 结果区 -> 分页区”三段式。
- 在 `BO-RULE-013` 中必须写明：列表主视图结果区下方不允许出现业务工作台、处理卡片、迁移动作面板、评估面板、映射维护面板等下置业务处理区；检测口径必须为“命名枚举 + 语义识别（评估/处理/迁移/映射/执行/工作台）”。
- 在 `BO-RULE-017` 中必须写明：若存在处理动作，承载方式必须迁移到弹窗、独立处理页或同页 Tab；不允许与列表主流程并列抢焦点。
- 必须写明：`data-block-whitelist` 不允许覆盖禁入规则；禁入项命中时必须阻塞。
- 必须写明：列表主视图分页视觉一致性为强制门禁，必须满足统一容器结构 `table-footer + summary + pagination`，否则必须 FAIL（阻塞）。
- 上述任一命中时，失败判定必须为 FAIL（阻塞），不得降级为建议项。

### 步骤 3：定义可复用模板片段

在规范文档中提供可复制模板：

- 页面目标与主任务模板
- 主/次/危险操作模板
- 字段映射模板
- 状态标签模板
- 反馈闭环模板
- 表格/筛选/分页闭环模板
- 主操作语义与选择机制模板
- 页面区块白名单模板

### 步骤 4：建立下游消费映射

明确三类下游消费关系：

- `ui-design-spec`：用 `BO-RULE` 回填设计基线与评审清单
- `prototype-build`：用 `BO-RULE` 执行构建期硬规则自检
- `prototype-check`：用 `BO-RULE` 执行开发前 Fail-fast 门禁

### 步骤 4.5：补充自动化检查映射表

- 在 `BACKOFFICE_UI_SPEC.md` 中新增“自动化检查映射表”，至少包含：
  - `BO-RULE` 编号
  - 检查类型（DOM / screenshot / click）
  - 选择器或区域
  - 预期行为
  - 失败阈值
  - 对应 `BUILD-RULE`
  - 对应 `UX-BLOCK`
- 对以下规则强制给出 click 检查映射：
  - `BO-RULE-002`（主操作唯一/位置一致）
  - `BO-RULE-008`（筛选-表格-分页闭环）
  - `BO-RULE-009`（主操作语义一致性）
  - `BO-RULE-012`（主任务首屏可见）
  - `BO-RULE-014`（跨屏依赖禁止）
  - `BO-RULE-015`（双主流程冲突禁止）
  - `BO-RULE-021`（分页语义与可达性）
  - `BO-RULE-022`（筛选后分页重置）

### 步骤 5：输出 Fail-fast 规则

至少包含以下 Fail-fast 项：

1. 信息层级不清晰
2. 主按钮不唯一或位置不一致
3. 文案出现技术字段直出
4. 状态颜色语义或禁用/可点击态缺失
5. 表格/筛选/分页闭环缺失
6. 主按钮文案为“选中/批量”但页面缺少选择机制或已选反馈
7. 页面出现未声明的功能卡片/区块
8. 页面类型与布局模板不匹配
9. 主任务关键区块首屏不可见
10. 列表页出现前置重表单压制主任务
11. 列表主视图结果区下方出现业务工作台/处理卡片/迁移面板/评估面板/映射维护面板
12. 关键任务路径跨屏依赖（滚动预算超限）
13. 同页双主流程冲突
14. 工具栏顺序或分页语义缺失
15. 筛选后分页重置规则缺失或违背

上述任一命中时，结论必须为 FAIL，且阻塞进入 `dev-implement`。

## Quality Gate（分层）

### P0 Gate（阻塞，最小必检）

- [ ] `BO-RULE-001~023` 全部存在，且每条均包含检查方式、失败判定、修复建议。
- [ ] `BO-RULE-011` 已明确列表主视图三段式结构（筛选区 -> 结果区 -> 分页区），且命中时必须 FAIL（阻塞）。
- [ ] `BO-RULE-013` 已明确“列表主视图结果区下方不允许业务处理区”，且命中时必须 FAIL（阻塞）。
- [ ] `BO-RULE-017` 已明确处理动作迁移路径仅允许弹窗/独立处理页/同页 Tab，且命中时必须 FAIL（阻塞）。
- [ ] 已明确“白名单不得豁免禁入项”；`data-block-whitelist` 命中禁入项时必须 FAIL（阻塞）。
- [ ] 已明确“命名枚举 + 语义识别”双通道禁入检测；未知命名命中评估/处理/迁移/映射/执行/工作台语义时必须 FAIL（阻塞）。
- [ ] 已明确列表主视图分页视觉一致性强制门禁：`table-footer + summary + pagination` 任一缺失或漂浮分页必须 FAIL（阻塞）。

## Example

示例：会员管理系统后台

- 页面：会员档案、状态/生命周期、等级规则、积分台账、权益定义
- 规范结果：
  - 主按钮固定为“提交变更/发布/保存”，每页仅一处主按钮
  - 所有状态显示为中文业务标签，不展示 `ACTIVE/FROZEN` 原始码
  - 列表页统一具备筛选区、结果区、分页区
  - 所有表单动作具备空态/加载态/失败态/成功态反馈
